24#include <string.h> /* For strlen */
25#include <mpi.h> /* For MPI functions, etc */

27const int MAX_STRING = 100;
28​
29int main(void) {
30 char greeting[MAX_STRING]; /* String storing message */
31 int comm_sz; /* Number of processes */
32 int my_rank; /* My process rank */
33​
34 /* Start up MPI */
35 MPI_Init(NULL, NULL);
Starts MPI. Every process runs this line.
36​
37 /* Get the number of processes */
38 MPI_Comm_size(MPI_COMM_WORLD, &comm_sz);
comm_sz = how many processes were started (mpiexec -n).
39​
40 /* Get my rank among all the processes */
41 MPI_Comm_rank(MPI_COMM_WORLD, &my_rank);
my_rank = this process's id, 0 to comm_sz - 1. This is the only thing that makes the processes behave differently.
42​
43 if (my_rank != 0) {
Same program in every process. The rank picks the branch.
44 /* Create message */
45 sprintf(greeting, "Greetings from process %d of %d!",
46 my_rank, comm_sz);
47 /* Send message to process 0 */
48 MPI_Send(greeting, strlen(greeting)+1, MPI_CHAR, 0, 0, MPI_COMM_WORLD);
Sends strlen+1 chars (the +1 is the '\0') to rank 0, tag 0.
49 } else {
50 /* Print my message */
51 printf("Greetings from process %d of %d!\n", my_rank, comm_sz);
52 for (int q = 1; q < comm_sz; q++) {
53 /* Receive message from process q */
54 MPI_Recv(greeting, MAX_STRING, MPI_CHAR, q, 0, MPI_COMM_WORLD, MPI_STATUS_IGNORE);
Waits for the message from source q, tag 0. Looping q = 1, 2, ... is why output is in rank order.
55 /* Print message from process q */
56 printf("%s\n", greeting);
Only rank 0 prints the workers' greetings. Workers never print.
57 }
58 }
59​
60 /* Shut down MPI */
61 MPI_Finalize();
62​
63 return 0;
64} /* main */

Each column is a rank. Each arrow is one message, pointing at the rank that receives it. A red cross means it never gets delivered. This shows one possible order: ranks that do not wait on each other can run in any order.

    • What this site is for:

      • Each code page lets you pick a rank and see only the lines that rank runs
      • Each message timeline can be stepped through, one send or receive at a time
      • MPI (Message Passing Interface): a C library for running one program as several cooperating processes
      • Every output shown here came from compiling and running the code with MPICH

    • What is covered so far:

      • Lecture 09: distributed memory systems, MPI basics, send and receive
      • Lecture 10: collective communication (Reduce, Allreduce, Bcast, Scatter, Gather)
      • Lecture 11: the trapezoidal rule, first with Send/Recv, then with Bcast and Reduce
      • Textbook: Chapter 3, sections 3.1 to 3.4
      • Code: mpi_hello.c, mpi_hello2.c, mpi_SendRec.c, mpi_Bcast.c and the makefile
      • Earlier lectures (pthreads, performance, heat distribution) are not on this site yet

    • A good study order:

      • Big ideas, then Reading MPI code, which is the routine to use on every exam question
      • Send and receive, then Collective communication, and try the lab on each page
      • Open each code page and predict the output before you read the notes
      • Finish with Hangs and mix-ups and the code-reading questions

    • Two things in the zip that can trip you up:

      • mpi_SendRec.c is the textbook's mpi_trap2.c, and mpi_Bcast.c is mpi_trap3.c
      • The comments inside those files still use the old names
      • The makefile builds mpi_hello, mpi_SendRec and mpi_Bcast, but not mpi_hello2
      • The trapezoid programs read input from the keyboard, so pipe it in: echo "0 3 1024" | mpiexec -n 4 ./mpi_Bcast

    • Compile and run:

      • mpicc -std=c99 -Wall -o mpi_hello mpi_hello.c
      • mpiexec -n 4 ./mpi_hello
      • -n 4 starts four processes
